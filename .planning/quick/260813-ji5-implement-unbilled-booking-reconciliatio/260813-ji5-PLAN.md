<objective>
Two related billing fixes, both scoped to the existing Phase 7/8 billing subsystem:

**Part A (always-on owner alert):** `checkEnforcementAndGetMembership` (src/billing/enforcement.ts) currently only sets `shouldAlert: true` when the business's enforcement policy is `'flag'`. When the policy is `'allow'` and a client books with no membership/capacity, the booking silently proceeds with no owner notification at all. Collapse the flag-only branch so any non-`'block'` policy (i.e. `'allow'` or `'flag'`) alerts the owner whenever `hasCapacity` is false — `'block'` keeps its existing `shouldAlert:false` (it never allows the booking to begin with).

**Part B (unbilled-booking reconciliation):** When an owner creates a NEW membership for a client who already has confirmed/pending bookings that predate any membership (and were therefore never billed), those bookings must be retroactively counted against the fresh package's starting session count — otherwise the client effectively gets free sessions. Add `getUnbilledBookingsForClient` to the billing query layer, wire it into `createMembership` (finite/session-counted packages only, atomic with the membership write, idempotent across renewals via the same onConflictDoNothing convention the renewed-sub-cant-book debug fix established), and surface both the retroactive-deduction count (owner confirmation message) and a per-client unbilled indicator (client-selection keyboard) in the payment-recording UI.

Purpose: Close two related billing gaps — owners with a permissive 'allow' policy currently have zero visibility into no-subscription bookings, and clients with pre-existing unbilled bookings currently get those sessions "for free" the moment a membership is created after the fact.
Output: `src/billing/enforcement.ts`, `src/billing/queries.ts`, and `src/telegram/handlers/payment-flow.ts` updated with matching test coverage in `tests/booking-enforcement.test.ts`, `tests/billing-unbilled-bookings.test.ts` (new), `tests/billing-membership-creation.test.ts`, and `tests/billing-payment-flow.test.ts`.

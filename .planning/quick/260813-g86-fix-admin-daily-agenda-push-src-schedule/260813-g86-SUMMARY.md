# Quick Task 260813-g86: Fix admin daily agenda push status filter Summary

**Fixed a silent scope bug where the 08:00 auto-pushed daily agenda excluded pending_owner_approval bookings — `runAgendaSweep` now passes the same `['confirmed', 'pending_owner_approval']` statuses array already used by the on-demand `/agenda` command and the AI owner-agent's schedule view.**

## Performance

- **Duration:** 12 min
- **Tasks:** 1 completed
- **Files modified:** 3

## Accomplishments
- `src/scheduler/agenda.ts`'s `runAgendaSweep` call to `listBookingsForDate` now explicitly passes `['confirmed', 'pending_owner_approval']` as the third argument, closing the blind spot where owners' 08:00 auto-push agenda silently under-reported pending bookings
- Added a dedicated regression test (`tests/calendar-agenda-reminder-queries.test.ts`, "Test 8") that isolates and mocks `runAgendaSweep`'s dependencies and asserts the exact statuses array is passed through — fails if the third argument is ever dropped again
- Kept `listBookingsForDate`'s own default parameter (`['confirmed']`) in `src/database/queries.ts` untouched — this was a call-site-only fix, as scoped

## Task Commits

Each task was committed atomically:

1. **Task 1: Fix runAgendaSweep's listBookingsForDate call and add regression test** - `7a64ccd` (fix)

## Files Created/Modified
- `src/scheduler/agenda.ts` - `runAgendaSweep`'s `listBookingsForDate` call now passes `['confirmed', 'pending_owner_approval']` as its third argument (was previously called with only 2 arguments, silently falling back to the function's own `['confirmed']` default)
- `tests/calendar-agenda-reminder-queries.test.ts` - Added a new `describe('runAgendaSweep status filter regression (agenda.ts)')` block with "Test 8", using `jest.isolateModules` + `jest.doMock` scoped to that single test to mock `'../src/database/queries'`, `'../src/telegram/client'`, and `'../src/utils/logger'` without affecting the file's other describe blocks (which deliberately mock only `'../src/database/db'` to exercise `queries.ts`'s real implementations)
- `tests/scheduler-agenda.test.ts` - Updated Test 3 and Test 6's `listBookingsForDate` assertions to include the new third argument (`['confirmed', 'pending_owner_approval']`), since `toHaveBeenCalledWith` requires an exact argument-count match and the source fix would otherwise have made these two pre-existing assertions fail

## Decisions Made
- Chose `jest.isolateModules` + `jest.doMock` (scoped per-test) over a file-wide `jest.mock('../src/database/queries')` in `tests/calendar-agenda-reminder-queries.test.ts`, because a file-wide mock would have auto-mocked every function that file's other describe blocks import and call directly against a mocked `db` (e.g. `claimAgendaSlot`, `findBookingsNeedingCalendarSync`), breaking Tests 1–7. This preserves the plan's requested test location while keeping all pre-existing tests in that file green.
- Left `src/database/queries.ts`'s `listBookingsForDate` default parameter and signature completely untouched, per the plan's explicit constraint — this is a call-site-only fix.

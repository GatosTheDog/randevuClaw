# Phase quick-261008-h82 Plan 01: Admin override of granted slots per client Summary

The owner can tell the Greek chat bot to give a named client a different number of classes than the package they paid for (set an exact balance, or add a signed difference), with a row-locked, clamped, ledger-audited update and a Greek before-to-after reply.

## What was built

- `adjustMembershipSessions(businessId, clientPhone, mode, sessions, idempotencyKey)` in `src/billing/queries.ts`. It locks the active membership via `getActiveMembershipForDeduction`, computes the new balance (set or add, clamped at 0), writes one `admin_adjustment` ledger row first (idempotent), then does an absolute update. It returns a discriminated result: `no_active_membership`, `unlimited_add_unsupported`, `unchanged` (same value or replay, no ledger row) or `updated`.
- `SetClientSlotsSchema` and `handleSetClientSlots` in `src/billing/tools.ts`. zod validation happens before any DB call. The handler returns Greek text (before and after joined by an arrow, the clamp note, the renewal caveat). The client is referred to by display name only.
- `set_client_slots` tool in `src/onboarding/ai-owner-agent.ts`. It has a declaration with required `client_name`, `mode` (`set|add`) and integer `sessions`, and no business or phone parameter. The executor case uses `resolveClientByName` (not-found and names-only disambiguation) and a single `withBusinessContext`. A system-prompt rule explains set versus add ("paid 8, gets 12" means add 4).
- `src/database/schema.ts`: comment-only note documenting `admin_adjustment` (no migration).

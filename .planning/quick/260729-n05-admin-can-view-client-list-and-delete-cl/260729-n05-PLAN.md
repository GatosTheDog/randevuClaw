<objective>
Two independent, unrelated fixes to the Telegram admin (business owner) menu in `src/telegram/handlers/admin-menu.ts`:

**Part A** — Add client deletion to the existing "Πελάτες" (clients) admin sub-menu. Today `showClientBalance` (the per-client detail screen reached via `menu:clients:balance:<relId>`) only offers a renewal-nudge button. This plan adds two destructive actions, each gated behind a Ναι/Όχι confirmation naming the client: **"Πλήρης διαγραφή"** (full GDPR-style erase of every DB row tied to that client for this business) and **"Αφαίρεση από λίστα"** (unlink-only — deletes just the `clientBusinessRelationships` row, leaving all booking/membership history intact).

**Part B** — Fix four nonsensical/incomplete Greek toggle-button labels in `showSettingsMenu` (missing "χωρίς", raw English "cutoff", a wrong-word "Επιτροπή" where "Έγκριση" belongs, and vague "ειδοποίηση" with no object) — a pure string-literal fix, no logic or callback_data changes.

Purpose: Part A closes a real GDPR gap (the project's own CLAUDE.md flags Greek user booking data as subject to GDPR) — there is currently no way for an owner to remove a client's data at all. Part B fixes labels a native Greek-speaking owner flagged as confusing/incorrect.

Output: Two new buttons + 4 new handler functions + 6 new switch cases in admin-menu.ts, 3 new query functions split across billing/queries.ts and database/queries.ts (matching existing table ownership), a new real-DB integration test file proving the cascade delete is FK-safe, and corrected Greek copy in the settings menu — all covered by automated tests.
</objective>

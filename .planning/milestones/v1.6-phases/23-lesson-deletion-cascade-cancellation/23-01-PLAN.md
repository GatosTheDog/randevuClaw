<objective>
Extend the two ALREADY-SHIPPED lesson-cancellation call sites (`handleClassCancelExecute` in admin-menu.ts, the `cancel_session` tool case in ai-owner-agent.ts) so that cancelling a session instance also cascade-cancels every active booking tied to it — flipping each booking to `'cancelled'`, restoring each client's session credit (reusing Phase 8's `restoreCredit`), releasing held capacity once per booking (reusing Phase 22's `releaseSessionCapacity`), and notifying each affected client in Greek — atomically and idempotently, per CLSS-07. CLSS-06 (the delete/cancel action itself) already works and is not touched by this plan except to call the new cascade function immediately after it succeeds.

Purpose: closes the "cancels the instance but silently ignores active bookings on it" gap called out in ROADMAP.md Phase 23 — today a cancelled lesson leaves affected clients' credit deducted, capacity held, and (for up to 6 hours) unnotified.

Output: a new `findActiveBookingsForSessionInstance()` query helper, a new `cascadeCancelSessionBookings()` service function shared by both call sites, both call sites wired to use it, and a comprehensive new real-DB integration test suite plus two lightweight wiring tests.
</objective>

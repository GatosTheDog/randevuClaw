<objective>
Give owners real approve/reject control over session-class (fixed_sessions) bookings instead of silent auto-confirmation, per D-01/OWNR-05/OWNR-06/OWNR-07. Session bookings currently auto-confirm via `bookSessionInstance()`; this plan makes that function default to `pending_owner_approval`, wires an inline Έγκριση/Απόρριψη keyboard on every new pending session booking, and makes rejection/expiry atomically release the held capacity and restore any deducted session credit — reusing the existing 2-hour expiry sweep, the existing `updateBookingStatusIfPending` CAS guard, and the existing `restoreCredit` helper exactly as locked in this planning session (no new poller, no new credit-restore path, no second locking strategy).

Purpose: Mirrors the Phase 13 slotless-request and Phase 2 open-slots approval patterns so session-class bookings get the same owner-gated correctness guarantees, closing the "currently auto-confirm with no owner say" gap called out in ROADMAP.md Phase 22.

Output: `bookSessionInstance()` defaults to pending with a capacity-holding, credit-deducting insert; a new `sbk:approve`/`sbk:reject` owner callback path with ownership + cross-tenant + idempotency guards; atomic capacity-release + credit-restore on both reject and expiry; the three owner-already-decided call sites (escalation exception, reschedule, direct assignment) explicitly preserved as immediate 'confirmed'; and a new real-DB test suite covering the atomic correctness plus updated/expanded webhook routing tests.
</objective>

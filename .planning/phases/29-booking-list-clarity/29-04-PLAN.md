<objective>
Fix the admin-side half of UX-02 (cancel-confirm prompts show real context instead of a raw instance id, D-08) and UX-04 (classes lists show the service name, D-10), close the admin-side half of UX-06's Layer 2 gap (unrecognized menu action, D-05.1), and consolidate all 11 inline occurrences of the admin back-menu button label into the shared constant from Plan 29-01 (D-07).

Purpose: `admin-menu.ts` is the entire admin `/menu` surface. Today, `showCancelClassConfirm` literally renders "Να ακυρωθεί το μάθημα #42;" — an admin has to already know which class #42 is before they can confidently confirm. `showClassesMenu`/`showCancelClassList` show only date/time, forcing the admin to guess which service a slot belongs to when a business runs more than one type of class. And any unrecognized menu tap (a stale button from before a bot restart, or a bug) leaves the admin looking at a bare error line with no way forward except typing `/menu` again from scratch.
Output: Admin sees real, contextual confirmation and list text everywhere in this file, and never hits a dead end on an unrecognized tap.
</objective>

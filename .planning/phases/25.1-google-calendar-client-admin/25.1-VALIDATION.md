## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | jest 29.7 + ts-jest (type-checks every test and the source files it loads: a stale typed fixture fails the whole suite) |
| **Config file** | `jest.config.js` (existing; `testMatch: **/tests/**/*.test.ts`) |
| **Quick run command** | `npx jest tests/calendar-*.test.ts tests/google-*.test.ts -i` |
| **Per-task command** | the explicit file list in the map below (never a bare `npm test`) |
| **Estimated runtime** | ~5 s per task command, ~60 s for the phase list in "After every plan wave" |

**Baseline facts (verified while planning, 2026-10-02):**
- A bare `npx jest` run reports 38 of 59 suites failing BEFORE this phase: the local Postgres (`randevuclaw_test` on localhost:5432) is reachable but its schema is stale (`column "booking_mode" of relation "businesses" does not exist`, fixed by plan 01 Task 2 step 4), hand-written fixtures are stale (tests/function-executor.test.ts, tests/calendar-sync.test.ts, tests/calendar-poller.test.ts), and `qrcode`/`sharp` are declared in package.json but not installed here, which breaks every suite that transitively imports `src/invites/generator.ts`. "Full suite green" is therefore not a usable gate. The gate is: every suite listed in the map passes, and no suite that passed at baseline regresses (baseline-passing examples: google-oauth, setup-google-calendar, telegram-client, escalation, client-escalation, billing-payment-flow, calendar-agenda-reminder-queries).
- tests/admin-menu.test.ts, tests/telegram-webhook.test.ts and tests/webhooks/client-menu.test.ts pass in this checkout once `../src/invites/generator` is mocked with a factory (plans 04 and 05 apply that one-line change). Their header warns that a bare `npm test` can crash the machine: always pass file paths.
- If `npm ls qrcode sharp` reports them missing, run `npm install` once (declared dependencies only; no new package is introduced by this phase).

## Sampling Rate

- **After every task commit:** run that task's command from the map (file list, `-i`)
- **After every plan wave:** `npx jest tests/calendar-*.test.ts tests/google-*.test.ts tests/admin-menu.test.ts tests/webhooks/calendar-confirmation.test.ts tests/webhooks/client-menu.test.ts tests/telegram-webhook.test.ts tests/function-executor-calendar.test.ts tests/ai-owner-assign-calendar.test.ts -i` (only files that exist yet) plus `npx tsc --noEmit`
- **Before `/gsd-verify-work`:** the wave list above fully passes, `npm run db:verify-25-1` prints all true, and the real-Postgres suites (`tests/calendar-queries.test.ts`, `tests/session-cascade.test.ts`) pass on a machine that has local Postgres with migration 0013 applied
- **Max feedback latency:** 30 seconds

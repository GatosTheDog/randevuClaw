### Known Implementation Issues

#### CR-01: Race Condition in Google Calendar Nudge (Stale Business Object)

**Severity:** Medium (UX correctness)

**Location:** `src/calendar/confirmation.ts:69-71` + `src/calendar/owner-nudge.ts:37-48`

**Issue:** The `processBookingConfirmedForCalendar` function receives a business object that may be stale. If another process completes Google OAuth between the initial fetch and the nudge check:
1. Booking confirmation fetches business (token is null)
2. Owner completes OAuth in parallel → token is set in DB
3. Confirmation code still has stale business object with null token
4. Nudge function checks stale object and sends (incorrectly)

**Mitigation in Place:**
- Atomic claim prevents multiple nudges from sending
- UX impact is limited: owner receives a misleading "connect your calendar" message when already connected
- Booking data is not corrupted; sync happens correctly

**Recommended Fix:**
Add a re-fetch inside `maybeSendGoogleCalendarNudge` before checking the token:
```typescript
const current = await findBusinessById(business.id);
if (!current || current.googleRefreshToken) return false;
```

**Status:** Documented in REVIEW.md as CR-01; not a blocker for goal achievement

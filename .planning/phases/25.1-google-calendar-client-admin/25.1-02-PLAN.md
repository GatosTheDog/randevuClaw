<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client-controlled text (Telegram first_name / username, service and business names typed by an owner) to calendar titles and URLs | Untrusted strings become Google event fields and URL query parameters |
| Google API error objects to logs | gaxios errors embed request bodies containing secrets |
| link recipient (client) | Anyone holding the Telegram message can read the URL |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25.1-06 | Tampering (parameter / URL injection, text injection) | buildClientCalendarLink, sanitizeCalendarText | high | mitigate | Every value passes through sanitizeCalendarText (control chars/newlines flattened, length capped) and encodeURIComponent; fixed host and path; tests parse the output with `new URL` and assert exactly five parameters even for names containing `&`, `=`, `#`; no parse_mode is used so no markup injection |
| T-25.1-05 | Information Disclosure (client-link data leakage) | buildClientCalendarLink | high | mitigate | Link contains only service name, business name, date and time (known to the client); no client name/id, no other client's data, no owner data; asserted by test |
| T-25.1-03 | Information Disclosure (refresh token / secret in logs) | describeGoogleError | high | mitigate | Only message/code/status/reason are copied; test proves secrets in `config.data` never appear in the described object |
| T-25.1-14 | Spoofing (forged invite via attendee parameter) | buildClientCalendarLink | low | mitigate | No attendee/add parameter exists; D-01 forbids invites; test asserts parameter set |
| T-25.1-SC | Tampering (supply chain) | dependencies | low | accept | No packages added in this plan |
</threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram callback_data / message text to bot logic | Untrusted input from owners and clients (already HMAC-verified at the webhook level) |
| bot to client chat | Calendar link and notes are delivered to a client's own chat |
| client-supplied display name / username to owner calendar | Untrusted strings become the owner's event title |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-25.1-05 | Information Disclosure (client-link data leakage) | confirmation points | high | mitigate | The link is built by plan 02 from service name, business name, date and time only; tests assert the client id never appears in the URL or the text; each link goes only to the booking's own clientPhone |
| T-25.1-04 | Elevation / cross-tenant | escl approve, slotless approve | high | mitigate | Existing owner-only and webhook-scoped business guards untouched; escl re-read booking must satisfy booking.businessId === ownerBusiness.id before any calendar work; helper receives the owner's own business row |
| T-25.1-06 | Tampering (text / URL injection via @username or first_name) | clientName capture, titles | medium | mitigate | Names are sanitised and length-capped by formatClientLabel/sanitizeCalendarText before they reach the owner event; the client link never contains a client name; messages are plain text (no parse_mode) so no markup injection |
| T-25.1-16 | Tampering (events or links for unapproved bookings, D-02) | approve branches | medium | mitigate | Helper only runs after a successful compare-and-swap (or committed confirmed insert) and itself refuses non-confirmed rows; tests cover reject and lost-race paths |
| T-25.1-07 | Denial of Service (Google latency inside the webhook transaction) | approve branches | high | mitigate | Plan 01 joins status writes to the transaction, plan 03 bounds Google calls at 8 s and never throws; client message is sent regardless |
| T-25.1-SC | Tampering (supply chain) | dependencies | low | accept | No packages added |
</threat_model>

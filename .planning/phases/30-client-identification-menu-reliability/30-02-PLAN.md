<objective>
Close the two known code-addressable gaps in Telegram persistent-menu-button reliability (ADMIN-05, D-06): (1) `finish_onboarding`'s one-shot, never-retried `setMyCommands`/`setChatMenuButton` calls get retry-with-backoff, since this call structurally fires exactly once in a business's entire lifetime; (2) every `/menu` tap re-asserts the same idempotent calls as a cheap hedge, since the underlying calls are safe to repeat.

Purpose: RESEARCH.md confirms Telegram's server-side menu-button state persists indefinitely once set correctly — the code gap is that a single transient failure at onboarding time had no second chance, ever. The remaining real-world unreliability (client-side app caching) is a documented platform limitation, not something either of these two hedges can or should try to fix.

Output: finish_onboarding retries its menu/command setup up to 3 times with exponential backoff before swallowing; showAdminRootMenu (called from both /menu entry points) re-asserts the same setup on every tap, non-blocking.
</objective>

<objective>
Give every one of the 5 CONF-01 destructive owner actions (delete_service, update_service_price, close_day, cancel_session, assign_client_to_session) a uniform confirm-before-mutate policy, whether triggered via the admin menu or a free-chat Gemini tool call — no action mutates data on its first invocation; a real Telegram button tap from the owner is always required first.

D-04 scope reminder: cancel_session already confirms today via the admin-menu path (`showCancelClassConfirm`) — this plan's job for that one action is only to make the FREE-CHAT path confirm identically, reusing the existing `menu:classes:cancel_yes/no` callback contract rather than inventing a parallel one. The other 4 actions currently have no admin-menu entry point at all (that arrives in Phase 28's ADMIN-04) — for those 4, this plan is the first and only confirmation gate.

Purpose: Closes the confused-deputy gap where a Gemini-parsed free-chat message could immediately delete a service, change a price, close a day, or assign a client with no human confirmation step — inconsistent with the approval discipline every session-booking mutation has followed since Phase 22.

Output: A new `src/utils/greek-messages.ts` constants file; `ai-owner-agent.ts`'s 5 tool cases send confirmations instead of mutating; a new confirm/abort dispatcher executes the previewed mutation on a real button tap; `telegram.ts` routes the new callback_data pattern to it.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Telegram client → webhook | Owner's Telegram app sends `otc:*` callback_query taps to `POST /webhooks/telegram/:webhookId`; attacker-shaped input until HMAC-verified + owner-identity checked |
| Gemini free-chat → executeOwnerTool | Owner's free-text Greek message is interpreted by Gemini into one of the 5 destructive tool calls, with LLM-parsed arguments |
| executeOwnerTool → pendingServicePriceChanges → handleOwnerToolConfirmCallback | The new price crosses a request boundary (tool-call time → button-tap time) via server-held in-memory state, never via client-supplied callback_data |

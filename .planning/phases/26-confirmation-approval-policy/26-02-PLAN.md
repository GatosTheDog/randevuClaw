<objective>
Convert the six free-chat owner tools named by D-04 (delete_service, update_service_price, close_day with update_hours, cancel_session, assign_client_to_session) from direct mutation into confirmation-prompt tools that reuse the senders and callbacks delivered by plan 26-01. After this plan, nothing in the owner agent mutates until the owner taps a confirm button, and the cancel-class path is literally the same prompt and executor as the admin menu.

Purpose: success criterion 1 (uniform confirmation regardless of entry path) and the requirement text "no action mutates immediately without confirmation".
Output: updated `src/onboarding/ai-owner-agent.ts`, rewritten `tests/ai-owner-cancel-session.test.ts`, new `tests/conf-01-free-chat-confirmation.test.ts`.

Design note (supersedes RESEARCH): RESEARCH proposed returning a `PENDING_CONFIRMATION:` string and relying on a prompt instruction to stop the loop. This plan instead uses the loop-break contract already in `aiOwnerAgent` (a tool result of an empty string returns immediately and the caller sends no extra reply), the same mechanism create_package and record_payment use. It cannot loop by construction, so the prompt addition is only an explanatory rule, not a safety dependency.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Owner free text to Gemini to tool call | model output is untrusted: it may hallucinate arguments, repeat calls, or call a destructive tool the owner did not intend |
| Tool arguments to callback_data | validated values are encoded into inline-keyboard callbacks that come back as untrusted taps (re-validated by plan 26-01) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-26-07 | Elevation of Privilege | executeOwnerTool destructive cases | high | mitigate | Tools perform no write: they only resolve a target and send a prompt; tests assert getConn, the business-context wrapper, cancelSession, cascadeCancelSessionBookings and bookSessionInstance are never called before a confirm tap |
| T-26-08 | Tampering | model-supplied arguments encoded into callback_data | medium | mitigate | Validators run before the prompt (day 0-6, HH:MM, cents 0..10000000 integer, client id 1-15 digits); service and class ids come from database reads (svcList, listSessions), never from model-supplied ids; plan 26-01 re-validates on tap |
| T-26-09 | Denial of Service | tool re-call loop after a confirmation request | medium | mitigate | Empty-string result returns from aiOwnerAgent on the first confirmation tool (existing loop-break contract); test asserts the Gemini create call count is 1; MAX_TOOL_ROUNDS stays as backstop |
| T-26-10 | Repudiation | model telling the owner an action is done before confirmation | low | mitigate | No success string is returned by these tools and no model text is produced after the prompt (loop ends); system prompt rule forbids claiming completion |
| T-26-11 | Information Disclosure | client name shown in the assign prompt | low | accept | Prompt is sent only to the authenticated owner chat |

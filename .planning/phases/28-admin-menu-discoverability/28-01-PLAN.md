<objective>
Wire the owner's two highest-frequency/highest-stakes setup actions into `/menu`: a root-level "Καταχώρηση Πληρωμής" button that reaches the already-built payment-recording flow (ADMIN-03, D-10/D-11/D-12), and three new Settings-submenu buttons that show 2-3 example Greek phrases for hours/services/class-setup so owners can discover what free-form phrasing the existing Gemini NLU agent already accepts (ADMIN-04, D-06/D-07/D-09). Also upgrades the "Νέο μάθημα (chat)" button from a single rigid example to the same multi-example style, closing ADMIN-02's named decorative-button gap (D-08).

Per D-13, none of this plan's new actions add Phase 26's Ναι/Όχι confirmation pattern: the payment button reuses `showClientSelection`'s own existing confirmation step unchanged, and the example-phrase prompts are purely informational (non-destructive, non-mutating).

Purpose: These are the phase's pure-wiring, zero-new-dependency changes — the underlying payment flow and AI agent already exist and work; this plan only makes them discoverable from `/menu`.
Output: An admin-menu.ts with 2 new callback_data families (`menu:payment`, `menu:settings:*_examples`) and one upgraded existing case (`menu:classes:create`), plus matching test coverage.
</objective>

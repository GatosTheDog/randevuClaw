<objective>
Rewire the two Telegram webhook entry points that currently dispatch an onboarding-incomplete
owner's input to the deterministic step machine (`dispatchOnboardingStep`) so they call the
new `aiOnboardingAgent` (built in Plan 21-01) instead. This is a routing-only change — no new
business logic — but it touches the one integration point PROJECT.md flags as having been
silently dropped once already (the onboarding-vs-menu routing check in `handleFoundBusiness`),
so the existing guard ordering must be preserved exactly, just re-targeted to the new agent.

Purpose: Make the new agent live on both channels an owner can use before onboarding
completes — typed free text and inline-keyboard taps — matching the D-02 stateless design
(no session lookup needed anymore, since aiOnboardingAgent re-derives everything from DB
state on every call).

Output: Updated `src/webhooks/telegram.ts` routing + a rewritten
`tests/webhooks/telegram-webhook.onboarding.test.ts` covering both entry points against the
new agent.
</objective>

<objective>
Build the new Gemini tool-calling onboarding agent as a standalone module, following the
exact pattern `aiOwnerAgent` (`src/onboarding/ai-owner-agent.ts`) already uses for
post-onboarding owner conversation. This plan produces the agent in isolation (tool
schemas, DB-state-derived system prompt, tool executor, MAX_TOOL_ROUNDS loop) with its own
test suite; wiring it into the Telegram webhook is Plan 21-02, and removing the old
step-machine is Plan 21-03.

Purpose: Replace regex/keyword-based free-text parsing (which rejects valid colloquial
Greek input — the motivating bug in `handleHoursRangeStep`) with Gemini NLU, and replace
step-index resumability with stateless DB-state re-derivation (D-02), while producing a
module that can be fully unit-tested before it is wired into the live webhook.

Output: `src/onboarding/ai-onboarding-agent.ts` (new) + `tests/onboarding/ai-onboarding-agent.test.ts` (new).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram message/callback -> aiOnboardingAgent | messageText/callback data is untrusted free text; business object is already HMAC-verified/resolved upstream by the webhook handler (Plan 21-02 wiring) before this module ever runs |
| aiOnboardingAgent -> Gemini API | Tool schema is the only channel through which Gemini output can cause a DB mutation — args are typed but not independently re-validated beyond required-field presence checks |
| executeOnboardingTool -> Postgres | Every mutating case must run inside withBusinessContext so RLS scopes the write to business.id |
| finish_onboarding -> Telegram Bot API | Rotates the live webhook registration for business.botToken — must never run against the wrong business |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-01 | Tampering | Prompt injection via owner free text | medium | mitigate | ONBOARDING_TOOLS is a fixed, closed set of function names/typed params; Gemini's function-calling API (same @google/genai mechanism already proven safe in ai-owner-agent.ts) cannot invent new tools or bypass the declared parameter shape; executeOnboardingTool's switch has a `default: unknown tool` branch that never executes arbitrary code |
| T-21-02 | Information Disclosure | Cross-tenant data leak in tool execution | high | mitigate | Every mutating executeOnboardingTool case wraps its DB write in withBusinessContext(business.id, ...) using getConn() (never raw `db`); business is a single object scoped per aiOnboardingAgent invocation, never a list — grep-verifiable per this plan's acceptance_criteria (zero raw `db` imports) |
| T-21-03 | Elevation of Privilege | finish_onboarding webhook rotation targeting the wrong business | high | mitigate | business.id/business.botToken passed into executeOnboardingTool come from the single `business` parameter fixed at aiOnboardingAgent's call site (resolved upstream from the HMAC-verified webhook path, per Plan 21-02) — never re-derived from Gemini tool args, so Gemini cannot redirect the webhook rotation to another business |
| T-21-04 | Denial of Service | Gemini free-tier quota exhaustion (15 req/min) from rapid onboarding messages | medium | accept | Pre-existing accepted risk shared with ai-owner-agent.ts and the client-facing ai-agent.ts (same GEMINI_API_KEY, same quota) — not a new surface introduced by this phase; MAX_TOOL_ROUNDS=5 bounds API calls per message; full backoff/circuit-breaker resilience is tracked separately as RESIL-01 in STATE.md Deferred Items, out of this phase's scope |
| T-21-05 | Tampering | Tool result tampering feeding back into the Gemini loop | low | accept | function_result text fed back to Gemini is always the trusted return value of executeOnboardingTool (in-app code), never raw user input passed through unmodified — same accepted pattern as ai-owner-agent.ts |
| T-21-SC | Tampering | npm/pip/cargo installs | n/a | accept | Zero new package installs in this plan (RESEARCH.md Package Legitimacy Audit: all libraries — @google/genai, drizzle-orm, zod — already approved dependencies from prior phases) |
